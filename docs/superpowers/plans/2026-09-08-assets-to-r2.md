# 2026-09-08 图片资产从 Postgres 迁到 R2（根治 /assets 内存超限）

## 背景与根因

`/assets/[id]?w=…&q=…` 图片变体路由（`lib/asset/handlers.ts` 的 `createGetAssetHandler`）在生产上间歇性 `exceededMemory`（Worker 128 MB 上限）返回 503，并连带杀掉同一 isolate 内的其它请求。根因：

- 图片二进制存在 Postgres `Asset.bytes`（730 条、220 MB、最大 3.6 MB、64 条超过 1 MB）。
- 每次变体请求都把整张原图从 Neon 读进内存（pg 的 bytea 走十六进制文本，解码前后两份），再 `Buffer.from` 拷一份、包成 `Blob` 喂 Images 绑定，输出再一份；`lib/asset/repoPrisma.ts` 还有 12 MB / 24 张的进程内原图缓存常驻。
- 文章页一次并发十几个图片请求（每张图 `?w=32&q=20` 占位 + 正式尺寸），几张大 PNG 同时处理就超 128 MB。

## 目标状态（本期）

1. 原图存 R2（桶 `seichigo-assets` 已创建，绑定名 `ASSET_STORE`），key `originals/<assetId>`。
2. 变体结果也存 R2，key `variants/<assetId>/w<width>-q<quality>.webp`，命中时直接流式返回，不碰原图。
3. 读路径全程流式：R2 对象流 → Images 绑定 `.input(stream)` → 输出。只有变体输出会被完整放进内存（几十 KB 级）。
4. 上传时归一化：非 GIF 的图片经 Images 绑定缩到最大宽 1600、转 WebP（质量 82）后再存；GIF/AVIF 原样存。
5. **回滚安全**：本期不删 `bytes` 列，不清空已有数据；新上传在写 R2 的同时仍写 `bytes`（写归一化后的字节）。任何时候回滚到上一个部署版本，旧代码只读 `bytes`，一切照常。清理 `bytes` 是下一期的事。
6. 本地开发（`next dev`，没有 R2 绑定）：自动回落到现有的 Postgres 路径（含 sharp 回落），行为不变。

## 数据模型改动（只增不删）

`prisma/schema.prisma` 的 `Asset` 新增可空字段：
- `storageKey String?` — R2 原图 key；为 null 表示尚未迁移，读路径回落到 `bytes`
- `byteLength Int?` — 归一化后原图字节数
- `width Int?`、`height Int?` — 归一化后尺寸（Images 绑定的输出 `.info()` 或响应头可得；拿不到就留 null，不要为此引入新依赖）

用 `prisma migrate dev --create-only` 生成迁移 SQL（只应含 `ALTER TABLE "Asset" ADD COLUMN …`），**不要在本机对任何库执行 `migrate deploy`/`migrate reset`**（生产迁移由我另行执行）。注意本仓库的 dev 库与 .env.local 里的生产库是两套，脚本默认连 dev 库。

## 代码改动清单

### A. R2 访问层 `lib/asset/store.ts`（新建）
- `getAssetStore(): AssetStore | null`，通过 `lib/anitabi/cf/bindings.ts` 的 `getCfBindings()` 拿 `env.ASSET_STORE`（需要在该文件的 `CfBindings` 类型上加 `ASSET_STORE?: R2Bucket`），拿不到返回 null。
- 方法：`putOriginal(id, body: ReadableStream | Uint8Array, contentType)`、`getOriginal(id): Promise<{ body: ReadableStream, contentType, size } | null>`、`getVariant(id, w, q)`、`putVariant(id, w, q, bytes)`。R2 写入带 `httpMetadata.contentType`。

### B. 仓库层 `lib/asset/repo.ts` / `repoPrisma.ts` / `repoMemory.ts`
- `Asset` 类型加上述新字段；`findById` **不再 select `bytes`**（用 Prisma `select`/`omit` 排除），新增 `findBytesById(id)` 只在回落时读 `bytes`。
- 删除 `repoPrisma.ts` 的进程内原图缓存（`assetReadCache` 全套）。
- `create(input)` 接受 `storageKey/byteLength/width/height`，仍写 `bytes`。
- `repoMemory.ts` 同步接口（测试用）。

### C. 读路径 `createGetAssetHandler`（`lib/asset/handlers.ts`）
顺序：
1. Cache API 命中 → 返回（保留现有逻辑）。
2. 解析变体参数；`findById` 取元数据（无 bytes）。
3. 有变体且可转换：先 `store.getVariant` → 命中则流式返回并 `cache.put`。
4. 未命中：原图来源 = `store.getOriginal(storageKey)`（有 storageKey 且 store 可用）否则 `findBytesById` 回落；喂 Images 绑定 `.input(stream)`，输出 bytes；`putVariant` 放进 `waitUntil`（用 `getCfBindings()?.ctx?.waitUntil`，拿不到就 await）；返回。
5. 无变体：有 storageKey → 直接把 R2 对象流返回（带 content-type、immutable 缓存头）；否则回落 `bytes`。
6. 保留 SVG/GIF 的现有安全处理与 `no-store` 语义。
7. 加一个模块级并发闸门：同一 isolate 同时最多 **3** 个"需要读原图并转换"的操作，超出的排队等待（简单 Promise 队列即可）。R2 变体命中不占闸门。
8. 去掉 `Buffer.from`/`Blob` 的重复拷贝，回落路径只保留一份 `Uint8Array`。

### D. 上传路径 `createPostAssetsHandlerWithOwner`
- 校验不变（类型白名单、`ASSET_MAX_BYTES`）。
- 若 Images 绑定可用且类型不是 gif：`IMAGES.input(file.stream()).transform({ width: 1600, fit: 'scale-down' }).output({ format: 'image/webp', quality: 82 })`，得到归一化 bytes 与 contentType `image/webp`；绑定不可用（本地）则不归一化。
- `store` 可用时 `putOriginal`，并把 `storageKey/byteLength` 写入 `create`；同时仍写 `bytes`（归一化后的）。
- `app/api/ai/assets/route.ts` 走的是同一个 handler，无需单独改。

### E. 存量迁移：管理端接口 `app/api/admin/assets/migrate/route.ts`（新建）
- `POST /api/admin/assets/migrate?limit=10`，管理员会话校验方式参照 `app/api/admin/seo/sync/route.ts`。
- 逻辑：取 `storageKey IS NULL` 的资产按 `createdAt` 升序取 `limit` 条，**逐条串行**处理：读 `bytes` → 非 gif 图片走 Images 归一化（同 D）→ `putOriginal` → 更新 `storageKey/byteLength/width/height`。**不修改 `bytes`**。
- 返回 `{ migrated: n, remaining: m, failed: [{id, error}] }`；单条失败记录后继续，不中断。
- 幂等：已有 storageKey 的跳过。
- 另加 `GET /api/admin/assets/migrate` 返回 `{ total, migrated, remaining }` 便于观察。

### F. 备份与恢复脚本（本机 Node，`scripts/`）
- `scripts/backup-assets.mts`：用 `pg`（项目已有依赖）连 `DATABASE_URL`，游标分批读 `Asset` 全表（含 bytes），逐行写 NDJSON（bytes 用 base64）并 gzip，输出到 `~/Backups/seichigo/assets-<ISO>.ndjson.gz`；结束打印条数、总字节、文件大小。读取 .env 的方式参照仓库其它 `scripts/*.mts`（先看一两个现有脚本）。**启动时打印目标 host 并要求 `--yes` 才实跑**。
- `scripts/restore-assets.mts --file <path> [--only-missing]`：把备份写回 `Asset`（`INSERT … ON CONFLICT (id) DO UPDATE SET bytes = EXCLUDED.bytes, …`），同样要 `--yes`。
- 两个脚本都不要在本任务中实际对生产执行，只保证 `npx tsx scripts/backup-assets.mts --help` 能跑。

### G. wrangler.jsonc
`r2_buckets` 新增 `{ "binding": "ASSET_STORE", "bucket_name": "seichigo-assets" }`，加一行中文注释（2026-09-08 图片资产迁 R2）。
