## 步骤 2：CUT-7

### 改什么

**`lib/planAgent/runLive.ts`**
- `Deps` 新增 `holdStartupFlush?: boolean`
- Writer 接口新增 `releaseStartupFlush(): void`
- 内部 `let startupHeld = deps.holdStartupFlush === true`
- status 分支：`statusChanged` 时若 `startupHeld` 则**只更新内存里的 statusText 与 dirty，不排 flush，直接 return**；否则照旧 `queueFlush()`
- `releaseStartupFlush()`：**未持有时严格 no-op**；持有时置 `startupHeld=false`，若 `dirty` 则 `queueFlush()`

**`lib/planAgent/execute.ts`**：`ExecutePlanAgentRunInput` 加 `deferStartupRunLive?: boolean`，透传进 `runPlanAgent` 的 deps。

**`lib/planAgent/loop.ts`**（或抽出去的 `loopPrelude.ts`）：
- 构造 writer 时传 `holdStartupFlush: deps.deferStartupRunLive === true`
- 在既有的 `afterModelRequestIssued()` 里**第一行**加 `runLiveWriter?.releaseStartupFlush()`（与 CUT-6 共用同一个释放点）

**`app/api/internal/plan-agent/run/route.ts`**：`executePlanAgentRun({ ..., deferStartupRunLive: process.env.PLAN_AGENT_STARTUP_RUNLIVE_DEFER === '1' })`。

### ⚠️ 硬性约束

- ⚠️ **释放点必须在首轮 `renewLease` 之后**（`afterModelRequestIssued()` 已经在 `createMessage` 之后、而 `renewLease` 在 `createMessage` 之前，所以天然满足——但要**写成代码注释 + 一条测试锁死**）。这是本刀相对今天的净安全性提升：被接管/被停止的 run 在 `renewLease` 就抛 `RunFencedError`，永远走不到释放点，**一条实况也不落库**；而今天的 flush#3 排在 `renewLease` 之前，反而可能以旧 token 落笔覆盖新 run 的实况行。后人若为再省 100ms 把释放点前移，就静默退回这个坏状态。
- ⚠️ `releaseStartupFlush()` 在内联 SSE 路径也会被无条件调用，**未持有时必须严格 no-op**，否则 SSE 路径凭空多一次 `upsertRunLive`。
- ⚠️ 三条 `emitStartup` status 事件**照常发出**（SSE 事件流逐字节不变），本刀只改 runLiveWriter 这条旁路的落库时机。
- ⚠️ 开关默认关。`process.env` 只在 route 层读，**不许在 loop.ts / runLive.ts 里读 env**（它们是纯依赖注入）。

### 已知的用户可见变化（写进注释）

观察流首帧分支是 `if (snap.live)` 才发，live 推送键是 `snap.live.updatedAt`。启动 flush 全部延后后，run 早期 `TripPlanRunLive` 行**根本不存在**，一个刷新页面的观察者拿到的首帧可能没有 live 载荷——由前端已有的「规划师思考中…」占位兜住。这是开关默认关、独立窗口上线的原因。

## 测试（§4.6，必须写）

`tests/planAgent/startupStatus.test.ts` 新增对称用例：
- 传 `deferStartupRunLive: true` → 启动段 `upsertRunLive` 调用次数为 **1**，首个 patch 的 `statusText === startupStatusPhrase('organize')`。
- 该次调用发生在 **`createMessage` 调用之后、且在 `renewLease` 之后**（调用顺序 spy）。
- 被接管的 stale run（`renewLease` 抛 `RunFencedError`）→ `upsertRunLive` **一次都不调**。
- 不传该 dep → 现有用例逐字不变、继续绿（它们断言首个 patch 是 `readHistory`）。
- `releaseStartupFlush()` 在未持有时是严格 no-op（不额外产生 `upsertRunLive`）。
