# 登录/注册页与验证码邮件跟随站点语言（2026-09-22）

## 现状（已核实，不用再查）
- `/auth/signin`、`/auth/signup` 两页（`app/auth/{signin,signup}/{page,ui}.tsx`）全部是硬编码中文；`middleware.ts` 把 `/en/auth/*`、`/ja/auth/*` rewrite 到同一套页面，所以英/日用户看到的也是中文（线上实测 `/en/auth/signin` 返回 `<html lang="zh">` + 中文 h1）。
- `components/layout/Header.tsx` 与 `components/layout/HeaderAuthControls.client.tsx` 里登录/注册链接固定写 `/auth/signin`、`/auth/signup`，没有按 locale 加前缀。
- 验证码邮件 `lib/email/templates/seichigoOtp.ts` 只有中文；`app/api/auth/request-code/route.ts` 不接收 locale；发信的调用方是 `components/auth/useEmailCodeLogin.ts`（POST `/api/auth/request-code`，body 只有 email）。
- 已经做对的、**不要动**：`components/auth/LoginModal.tsx` 已用 `t('auth.modal.*', locale)`，三语字典 `lib/i18n/locales/{zh,en,ja}.json` 里 `auth.modal` 齐全；`components/plan/PlanStartView.tsx` 会把 locale 传给它。
- 语言解析统一用 `lib/i18n/resolveRequestLocale.ts`（路径前缀 > NEXT_LOCALE cookie > accept-language > zh）。middleware 在 rewrite 时已把原始路径与解析结果放进请求头 `x-seichigo-pathname` / `x-seichigo-locale`（见 `middleware.ts` 第 93–96 行），服务端组件可以从 `headers()` 读。
- 路径加前缀的现成工具：`components/layout/prefixPath.ts` 的 `prefixPath(path, locale)`——先读它的规则，它对某些路径有白名单，`/auth/*` 可能不在其中；需要的话扩展它而不是另写一个。

## 要做的

### A. 登录/注册页三语
1. 在三语字典里新增 `auth.signin.*` 与 `auth.signup.*`（页面标题、副标题、tab 名「邮箱登录/账号密码登录」、字段标签、占位符、按钮、各类错误与提示文案、页脚同意条款、metadata title/description）。中文原样搬现有文案；英文、日文由你写，语气与 `auth.modal` 一致（简洁、不卖萌）。
2. `app/auth/signin/page.tsx`、`app/auth/signup/page.tsx`：服务端用 `headers()` 取 `x-seichigo-locale`（缺失时用 `resolveRequestLocale` 兜底），把 locale 传给客户端组件，并用它生成 `generateMetadata`（title/description 三语）。`alternates.canonical` 保持 `/auth/signin`、`/auth/signup`（不要给英日路径做 canonical，这些页本来 noindex/不进 sitemap，别改索引策略）。
3. `SignInClient` / `SignUpClient` 接收 `locale` prop，所有文案改 `t()`；`useEmailCodeLogin.ts` 里如有硬编码提示文案也一并接 locale。`<html lang>` 由根 layout 决定，如果根 layout 取的是同一份头信息就顺带对了；如果不是，不要为此改根 layout，只在汇报里说明。
4. 页面内的链接（登录页里「去注册」、注册页里「去登录」等，如有）与 `Header.tsx`、`HeaderAuthControls.client.tsx` 的登录/注册链接按 locale 加前缀（zh 不加，en/ja 加 `/en`、`/ja`）；`callbackUrl` 参数原样保留。`app/(authed)/**` 里 `redirect('/auth/signin?callbackUrl=...')` 的服务端跳转不用改。

2. `app/api/auth/request-code/route.ts`：body 增加可选 `locale: z.enum(['zh','en','ja'])`；没传时用 `resolveRequestLocale({ pathname: '/', cookieHeader, acceptLanguage })` 从请求头推断。把 locale 传给两个 render 函数。API 的错误消息字符串（`邮箱格式不正确` 等）也按 locale 返回三语。
